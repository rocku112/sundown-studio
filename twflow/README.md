# twflow — 台股板塊資金流

盤後彙整三大法人買賣超，呈現資金在產業板塊間的流向。

> 本專案僅就臺灣證券交易所、證券櫃檯買賣中心之公開資料進行彙整與統計呈現，
> 非證券投資顧問事業，不對特定有價證券提供分析意見或推介建議，
> 亦不構成任何投資建議；投資人應自行判斷並自負盈虧。

排行榜每列的「幾檔在買」與「主力」會跟著選定期間重算 —— 用固定 5 日版本的話，
當日榜會出現「今天買超 +49.8 億」配上「主力 -31.1 億」這種看似矛盾的組合。

### ④ 的結果（樣本外，訓練 29 日 → 測試 30 日）

顯著內聚 ＝ 該組中位兩兩相關 > 同尺寸隨機組的 p95。

| 分類來源 | 顯著內聚比例 | 測試段中位相關 |
|---|---|---|
| Tide 手工 108 板塊 | 57.9% | 0.196 |
| 官方自報 原始名單 | 45.2% | 0.115 |
| **官方自報 → 相關性剪枝後** | **59.8%** | **0.236** |

- 74.6% 的組別在樣本外相關提升；68 組由不顯著轉為顯著，18 組反向
- 平均剪掉 26.9% 的成員，剪枝後規模中位數 7 檔
- 去極值（±3SD）與移除 +7.98% 那個極端日重跑，三種算法排序不變

剪掉的正是自報灌水者：台達電（自報 68 節點）被從「專用機械」「休閒車業」剔除，
大同（43 節點）被從「電視」「鋼鑄鐵元件」剔除。

**但剪枝不會憑空生出板塊。** 官方沒有的 54 個題材板塊（液冷散熱、矽光子與 CPO、
玻璃基板、HBM、CXL⋯⋯）仍須另建，那是階段 ⑤。

## 執行

```bash
pip install -r requirements.txt
python scripts/fetch_ic_chain.py          # 產業鏈骨架（有快取，重跑不重抓）
python scripts/fetch_market.py --days 60  # 價量＋法人（首次約 8 分鐘，之後只抓新日）
python scripts/prune_sectors.py           # 相關性剪枝
python scripts/validate_pruning.py        # 樣本外驗證
python scripts/discover_themes.py         # 題材發掘
python scripts/build_sectors.py           # 組板塊表
python scripts/build_web.py               # 產生前端資料（個股、走勢、今日重點）
python scripts/build_events.py            # 籌碼異動事件流（自選股通知欄）
python scripts/build_chains.py            # 供應鏈上下游資金重心
python scripts/snapshot.py                # 打包單檔可離線開的 snapshot.html
python scripts/sanity_check.py            # 合理性檢查（CI 用，失敗回非 0）
python scripts/diff_vs_tide.py            # 與 Tide 比對（可選）
```

看畫面：`python -m http.server 3004 --directory web`，或直接開 `web/snapshot.html`。

加 `--force` 忽略快取重抓。TWSE 會擋高頻請求，內建 2 秒延遲與指數退避。

## 自動化

| 排程 | 做什麼 | 為什麼分開 |
|---|---|---|
| `twflow-daily.yml` 每交易日 18:40(TW) | 抓新的一天 → 重算板塊指標 | 數字每天更新 |
| `twflow-weekly.yml` 每週日 | 重算分類（剪枝＋題材發掘） | **分類表要穩定**。天天重算會讓成分股天天變，使用者昨天看到「散熱模組 6 檔」今天變 8 檔，會以為數字在亂跳 |

週更若跑出未命名的新題材群，會自動開 issue 提醒，不會靜默留在圖上。

### 籌碼異動事件

`build_events.py` 產出 `web/data/events.json`，前端用自選股過濾。門檻：

| 事件 | 門檻 | 當日覆蓋率 |
|---|---|---|
| 異常大買／大賣 | 當日淨額 > 該檔近 20 日日均絕對進出 × 2.5 | 1.6% / 1.0% |
| 法人連買 | ≥ 7 天 | 3.2% |
| 法人連賣 | ≥ 5 天 | 3.3% |
| 外資連買 | ≥ 7 天 | 3.4% |

目標是每類約 3%，這樣追蹤 20 檔的人一天收到 2~3 則。第一版沿用 Tide 的
「連買5／連賣3」跑出 591 則/日（30% 的市場），那不是事件是常態。

⚠️ 實測發現法人**連買**天數的分布比連賣密集（≥2 天：28.3% vs 20.4%），
與直覺相反，所以是連買門檻要更嚴。門檻在 60 天窗期上校準，歷史拉長後要重校；
`sanity_check.py` 會在覆蓋率飄出 2%–25% 時擋下來。

### 供應鏈重心

`build_chains.py` 產出 `web/data/chains.json`。**這是 Tide 架構上做不到的事** ——
他的 108 個板塊是平的，我們有官方產業價值鏈的上／中／下游拓撲。

| 欄位 | 意義 |
|---|---|
| `side` | 整條鏈近 5 日淨額的方向（買超／賣超）|
| `focus` | 那股力道集中在哪一段。0＝上游、0.5＝中游、1＝下游 |
| `label` | 由**實際占比**產生（≥60% 才說「集中在X」，否則「分散於…」）|
| `shift` | focus 較前 5 日的移動。**方向不同的兩期為 null** |

只取「與整鏈同向」的段計算重心：鏈被買時看哪幾段在被買，鏈被賣時看賣壓分布。

⚠️ 第一版用 `(下游 − 上游)/(|上|+|中|+|下|)`，錯的。雲端運算上游 −231 億、
下游 +31 億會被算成「錢全在下游」，但那是整條鏈被倒貨、下游相對抗跌，
分子分母混用了流入與流出。且沒有規模下限，±1 億的鏈也會跳出極端值。

⚠️ 標籤不能從重心推。電機機械只有上游與下游兩段，重心 0.40 四捨五入成 0.5，
第一版標成「集中在中游」——那條鏈根本沒有中游。改成看實際占比後
`sanity_check.py` 也加了對應的守門。

⚠️ **跨鏈不可加總**：同一檔股票可能同時屬於半導體與通信網路，兩條鏈各自
完整計算它。每條鏈只在自己內部有意義。

### 推播

**目前只有應用內通知欄，沒有真正的 Web Push。** Service Worker 的 `push`
事件處理已備好，缺的是後端——Web Push 必須有地方儲存訂閱端點（`endpoint`），
純靜態站做不到。要啟用需要：

1. 一個能被前端寫入的儲存（Supabase 免費額度即可，只需一張
   `push_subscriptions` 表，RLS 只開 insert/delete）
2. 產一組 VAPID 金鑰，私鑰放 GitHub Secrets
3. 在 `twflow-daily.yml` 盤後步驟後加一段：讀 `events.json` 比對訂閱者的
   監控清單 → `pywebpush` 發送

沒接之前，使用者仍能靠「加到主畫面 + 未讀徽章」形成回訪習慣，
只是要自己打開才看得到。

### 儲存模型

`data/market/days/YYYY-MM-DD.json` 是真源，**append-only、寫完不再變動**，
欄式格式約 125 KB/天（一年 32 MB）。`panel.json` 由它們推導、不進版控——
它 7 MB 且每天整份改寫，進版控會讓 git 歷史以 GB 計。

## 已知的設計決策

**日報酬自己從收盤價算**，不用官方的「漲跌」欄位 —— 兩個市場格式不同
（TWSE 用 HTML 標籤帶顏色），停牌/無成交時給法也不一致。自己算至少全市場同一把尺。

**買賣超金額（億）= 買賣超股數 × 當日收盤價 ÷ 1e8**。這是估算，不是實際成交金額。

**外資 = 外陸資（不含外資自營商）+ 外資自營商**，與市場慣例一致。
自營商拆「自行買賣」與「避險」兩欄分開存 —— 避險是發權證後的被動調整，
與看多看空無關，多數用途應只看自行買賣。

**普通股篩選 = 4 位數字且不以 0 開頭**，排除 ETF、權證、存託憑證。
得到 1974 檔，與 Tide 的 1978 檔幾乎一致。

**官方產業鏈是公司自報的**，嚴重超額歸屬（47.8% 個股屬於 2 個以上節點，
台達電自報 68 個）。它是字典不是分類表 —— 給詞彙與候選池，不給選擇。
選擇由 `prune_sectors.py` 的相關性檢查 + 人工覆核決定。
