## 1. 產品定位

**一個 APP、兩個市場、一條時間線：**

```
美股收盤 04:00/05:00 ─→ 06:30 美股晨報 ─→ 09:00 台股開盤 ─→ 13:30 收盤
   ─→ 18:40 台股盤後（twflow 法人資料）─→ 21:30/22:30 美股開盤 ─→ …
```

台灣投資人的一天剛好被兩個市場接力填滿。APP 依時間自動把首頁切到「現在最該看的那個市場」。

### 目標使用者
1. **台美股都有買的人**（台股帳戶＋複委託／海外券商）—— 需要一個地方同時管兩邊的自選股
2. **只做台股、但每天早上要先看美股的人** —— 想知道昨晚美股對今天台股的影響
3. **只做美股的台灣人** —— 需要中文、台灣時間、台灣稅務視角

### 差異化
| 別家 | 我們 |
|---|---|
| 台股 APP（籌碼 K 線、CMoney）美股很弱 | 兩邊都是一級公民 |
| 美股 APP（Yahoo、TradingView）沒有台股籌碼、英文為主 | 台股有三大法人／板塊資金流（twflow 既有）|
| 兩邊各看各的 | **台美連動**：用 twflow 的 28 條產業鏈把美股龍頭接到台灣供應鏈 |

完全中文、免帳號、免費、PWA，延續 SunDown Studio 既有產品風格。

## 2. 與既有 twflow 的關係

twflow 已完成台股板塊資金流（泡泡圖、排行榜、個股頁、自選股、籌碼異動、供應鏈、PWA）。

**建議：把 twflow 升級成雙市場 APP，而不是另開一個新產品。**

- 台股資料管線、前端元件、自選股機制、PWA 全部直接沿用
- 美股作為第二個市場加進來，共用同一套頁面框架
- 目錄：`twflow/` 維持台股管線；新增 `usflow/`（美股管線）；前端合併成一個 `web/`
- twflow 現有網址保留，避免既有使用者失聯

> 若之後決定分成兩個獨立產品，資料管線本來就是分開的，拆開成本低。

## 3. 兩個市場的資料不對稱

美股**沒有**台股那種每天公布的「三大法人買賣超」。同一個功能在兩邊要用不同訊號：

| 想知道的事 | 台股 | 美股替代 | 頻率 |
|---|---|---|---|
| 大資金在買什麼 | 三大法人買賣超（官方）| 板塊 ETF 成交值 × 漲跌（代理指標）| 日 |
| 空方力道 | 融資融券 | FINRA 每日 short volume | 日 |
| 內部人動向 | 董監持股異動 | SEC Form 4 | 事件 |
| 機構持股 | 投信持股 | SEC 13F（季報，延遲 45 天）| 季 |
| 營收 | **月營收**（台股特有）| 無，只有季報 | 月／季 |
| 財報 | 季報 | SEC XBRL companyfacts | 季 |

**UI 原則：同一個欄位名稱，兩個市場必須是同一件事。** 美股的代理指標一律叫「板塊熱度」，
不可沿用「法人買超」字樣；沒有對應資料的欄位直接不顯示，不硬湊。

## 4. 功能規劃

### 共用框架
| 頁面 | 台股 | 美股 |
|---|---|---|
| **首頁（依時段）**| 盤後：今日情緒、資金流入流出（twflow 既有）| 晨報：四大指數、費半、VIX、美債、美元；11 大板塊熱力圖 |
| **板塊** | 泡泡圖＋排行榜（既有）| 板塊熱度泡泡圖（同視覺）|
| **個股頁** | 走勢、法人分項、所屬板塊（既有）＋月營收、EPS、殖利率 | 走勢、EPS／營收／毛利率、殖利率、財報日、做空比例 |
| **自選股** | **一份清單同時放台美股**，可依市場篩選 | 同左 |
| **事件流** | 籌碼異動（既有）| 內部人大額買進、做空異常、財報公布 |
| **搜尋** | 1979 檔（既有）| 先涵蓋 ~650 檔，中英文名稱都能搜 |

### 跨市場功能（核心差異化）
| 功能 | 說明 |
|---|---|
| **台美連動** | 美股龍頭 → 台灣供應鏈對照（NVDA → 鴻海、廣達、緯創…），帶出這些台股在 twflow 的最新法人動向 |
| **ADR 溢價** | 台積電、日月光、聯電、中華電：ADR 換算台幣後 vs 台股收盤價 |
| **雙上市個股頁** | 2330 與 TSM 在同一頁切換，並列兩邊走勢與溢價 |
| **今日台股觀察名單** | 依昨晚美股板塊表現，列出台灣供應鏈中相關的個股（只列關聯，不給買賣建議）|
| **跨市場資產總覽** | 自選股可輸入持股，台幣／美元統一換算，含美股股利扣 30% 預扣稅後的「實拿」|

### 明確不做
- 即時報價、下單、帳戶串接、個股評等、目標價、買賣訊號（法遵考量，見 §9）

### 台股（已實測，twflow 使用中）

### 美股（全部需在 Phase 0 實測）
| 用途 | 候選來源 | 備註 |
|---|---|---|
| 公司清單／CIK 對照 | `www.sec.gov/files/company_tickers.json` | 官方、免費；需帶含聯絡 email 的 User-Agent |
| 基本面 | `data.sec.gov/api/xbrl/companyfacts/CIK##########.json` | 官方、免費；限速 10 req/s |
| 內部人 | SEC EDGAR Form 4 | 官方 |
| 做空量 | `cdn.finra.org/equity/regsho/daily/CNMSshvolYYYYMMDD.txt` | 官方、免費 |
| 日線價量 | Stooq CSV／其他免費日線來源 | **最大風險**：非官方，可能改版或限流，需備援 |

### 共用
| 用途 | 來源 |
|---|---|
| 匯率 | 台灣央行／臺銀牌告（ADR 溢價、資產換算）|

**美股價量來源是整個專案最脆弱的一環。** 抓資料的那一層要寫成可替換來源的介面，至少準備兩個來源，
並沿用 twflow 的 `sanity_check.py` 作法：數字不合理就不提交。

## 6. 系統架構（零伺服器，沿用 twflow）

```
GitHub Actions
  ├─ twflow-daily.yml（既有）  台灣 18:40  台股盤後
  │    └─ 新增：月營收（每月 10 日後）、股利／EPS（季）
  ├─ usflow-daily.yml（新）    台灣 06:30  美股盤後（週二～週六）
  │    ├─ fetch_prices.py   只抓缺的交易日，逐日檔 append-only
  │    ├─ fetch_finra.py    每日做空量
  │    ├─ fetch_sec.py      每週；只更新有新 filing 的公司
  │    └─ sanity_check.py
  └─ 兩邊跑完都觸發 build_cross.py（新）
       ├─ ADR 溢價（需要兩邊最新收盤＋匯率）
       └─ 台美連動、觀察名單
        ↓ commit
GitHub Pages：單一前端 PWA，讀 tw/、us/、cross/ 三組靜態 JSON
```

- 兩條管線 concurrency group 分開，互不阻塞；`build_cross` 用 concurrency 鎖避免同時寫
- 美國夏令／冬令時間差 1 小時，06:30 排程兩者都安全
- 兩邊假日不同（台股颱風假、美股感恩節）：各自「當日無資料就跳過」，跨市場計算以各自最新交易日為準並標示日期

### 資料格式統一
```json
{ "market": "TW", "code": "2330", "name": "台積電", "currency": "TWD", ... }
{ "market": "US", "code": "TSM",  "name": "台積電 ADR", "currency": "USD", ... }
```
所有個股以 `market:code`（如 `TW:2330`、`US:TSM`）為唯一鍵，自選股與搜尋都用這個鍵。
既有 twflow 的 localStorage 自選股需做一次遷移（舊格式只有代號 → 補上 `TW:`）。

### 資料量
- 台股：既有 1979 檔 × 60 日
- 美股：~650 檔 × 60 日 × ~50 bytes ≈ 2 MB，與台股同量級
- SEC companyfacts 原檔很大，**只萃取需要的欄位**再落檔，原檔不進 git

## 9. 法遵與風險

- 沿用 twflow 免責聲明：僅彙整公開資料，非投顧，不構成投資建議
- 不做個股評等、目標價、買賣訊號；「觀察名單」措辭需審慎（僅列關聯）
- SEC 要求 User-Agent 帶真實聯絡資訊並遵守限速
- 非官方價量來源的條款需確認是否允許自動抓取與再散布

| 風險 | 影響 | 對策 |
|---|---|---|
| 美股免費價量來源失效 | 美股端停擺 | 可替換來源＋雙來源＋sanity check；台股端不受影響 |
| 兩市場同名欄位意義不同 | 誤導使用者 | §3 原則：同名必同義，代理指標另取名 |
| 自選股格式遷移 | 既有用戶清單遺失 | 遷移前備份到另一個 localStorage key |
| 台美對照表主觀 | 公信力 | 標註依據，用相關性驗證 |
| 前端合併後變肥 | 手機載入慢 | 依市場分頁延遲載入 JSON |
